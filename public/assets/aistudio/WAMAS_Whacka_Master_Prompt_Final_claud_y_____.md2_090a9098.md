## ═══════════════════════════════════════
## 🔷 الجزء الأول: هوية التطبيق ونظرته العامة
## ═══════════════════════════════════════

أنت تبني تطبيق **WAMAS** — نظام تشغيل أعمال متكامل (Business Operating System) مخصص لإدارة محلات تأجير وبيع مستلزمات الأعراس (فساتين، كوش، طاولات، كراسي، إكسسوارات، وخدمات).

### الهدف الأساسي للتطبيق:
إدارة الدورة التجارية الكاملة من أول تواصل مع العميل حتى إغلاق العقد واسترجاع التأمين، في منظومة واحدة مترابطة تجمع:
- **التأجير والحجوزات** (الوظيفة الأساسية)
- **المبيعات والفواتير**
- **إدارة المخزون والأصناف**
- **التأمينات والضمانات**
- **المحاسبة المالية**
- **إدارة علاقات العملاء (CRM)**

### المبدأ الجوهري:
> "الحجز والتأجير والمخزون والمحاسبة دورة واحدة مترابطة — كل حدث تجاري يولّد جميع آثاره تلقائياً"

### الدورة الأساسية للتطبيق:
```
عميل ← حجز ← عربون ← عقد ← تأمين ← تجهيز ← تسليم ← إرجاع ← فحص ← تسوية ← إغلاق
```

### المنصة والواجهة:
- **Web App (PWA)** + **تطبيق جوال (iOS & Android)**
- **اللغة:** عربية RTL بالكامل (مع دعم إنجليزي جانبي)
- **الألوان:** بنفسجي ملكي / ذهبي / أبيض ناصع (ألوان الأعراس الفاخرة)
- **الخط:** Tajawal أو Cairo (خط عربي واضح ومريح)
- **الأيقونات:** Lucide Icons
- **التصميم:** نظيف، احترافي، سريع، مناسب لموظفي الاستقبال والكاشير

### 📅 الوحدة 3: محرك الحجوزات (الأهم - Anti-Conflict Engine)

**قاعدة التعارض الرياضية (يُطبَّق على مستوى قاعدة البيانات):**
```
التعارض يحدث إذا: existingStart < requestedEnd AND existingEnd > requestedStart
```

**آليات منع الحجز المزدوج (Double Booking Prevention):**
1. قفل الصنف مؤقتاً 10 دقائق عند بدء عملية الحجز
2. فحص التداخل الزمني عند كل حجز جديد قبل الحفظ
3. هامش أمان إجباري (Buffer): 48 ساعة قبل وبعد كل حجز للغسيل والكي
4. Optimistic Locking بـ version_number على كل سجل
5. عرض أقرب بديل متاح تلقائياً عند الرفض

**حقول الحجز:**
- رقم الحجز التسلسلي (فريد)، العميل، قائمة الأصناف، تاريخ البدء، تاريخ الانتهاء
- المدة (يوم / أسبوع / مخصص)، إجمالي السعر، الخصم (بحد صلاحية الموظف)
- العربون المطلوب (25% كحد أدنى)، مبلغ التأمين (30% كحد أدنى)، الضريبة، ملاحظات

**حالات الحجز (8 حالات):**

| الحالة | الوصف |
|--------|-------|
| PENDING | بانتظار دفع العربون |
| DEPOSIT_PAID | دُفع العربون |
| CONFIRMED | مؤكد — القطعة مقفلة للعميل |
| PREPARING | قيد التجهيز والخياطة |
| READY | جاهز للتسليم |
| DELIVERED | مُسلَّم للعميل |
| RETURNED | مُعاد من العميل |
| COMPLETED | مكتمل وتمت التسوية |
| LATE | متأخر (تلقائي بعد تجاوز الموعد) |
| CANCELLED | ملغي مع تطبيق سياسة العربون |

**التقويم التفاعلي:** يومي / أسبوعي / شهري / حسب الصنف / حسب الفئة / حسب الفرع — مع ترميز لوني لكل حالة

**سياسة الإلغاء (قابلة للإعداد):**
- أكثر من 30 يوم → استرداد كامل
- 15-30 يوم → استرداد 50%
- أقل من 7 أيام → لا استرداد

### 📋 الوحدة 4: عقود التأجير (الدورة الكاملة)

**12 مرحلة متسلسلة:**

| # | المرحلة | الأثر التلقائي |
|---|---------|----------------|
| 1 | تسجيل العميل + المناسبة | إنشاء ملف CRM |
| 2 | اختيار الأصناف + التواريخ | تحقق التوفر + قفل الصنف |
| 3 | دفع العربون (≥25%) | PENDING → CONFIRMED |
| 4 | توقيع العقد رقمياً | PDF + أرشيف قانوني |
| 5 | تحصيل التأمين | قيد التزام في المحاسبة |
| 6 | التجهيز (خياطة + غسيل) | PREPARING → READY |
| 7 | التسليم بمسح QR + صور | DELIVERED + قيد محاسبي |
| 8 | فترة الاستخدام | عداد التأخير يبدأ |
| 9 | الإرجاع بمسح QR + فحص | RETURNED + Inspection |
| 10 | تقييم التلف والتأخير | احتساب الغرامات |
| 11 | التسوية وخصم الغرامات | قيد تسوية + رد الباقي |
| 12 | إغلاق العقد | COMPLETED + CLEANING |

**احتساب التأخير والتلفيات:**
- غرامة التأخير = أيام التأخير × 15% من سعر اليوم (قابل للإعداد)
- الحد الأقصى = قيمة التأمين الكاملة
- مبلغ الرد = التأمين - (غرامة التأخير + رسوم التلف + تكلفة الفقدان)
- إذا كانت النتيجة سالبة → مديونية إضافية على العميل

**مرفقات العقد:** صورة الهوية، صور الصنف قبل وبعد، توقيع إلكتروني، PDF A4، رابط واتساب

#### 📸 7.1 — صور المنتجات والفساتين (Product Gallery)

**كل صنف (فستان / كوشة / طاولة / غيره) يملك:**

| الحقل | التفاصيل |
|-------|----------|
| **الصور الرئيسية** | 1 إلى 10 صور — زوايا مختلفة (أمام / خلف / جانب / تفصيل) |
| **صورة الغلاف (Thumbnail)** | صورة واحدة تظهر في البطاقات والقوائم — يختارها الموظف |
| **فيديو تعريفي** | فيديو قصير اختياري (حتى 60 ثانية) |
| **صور المقاسات والتفاصيل** | تفصيل القماش / التطريز / الأزرار / الذيل |
| **صور ما قبل الصيانة** | تُرفع تلقائياً عند إنشاء أمر صيانة |
| **صور ما بعد الصيانة** | تُرفع عند إغلاق أمر الصيانة |

**خصائص ألبوم المنتج:**
- رفع الصور مباشر من الكاميرا (موبايل) أو من الجهاز
- ضغط تلقائي للصور مع الحفاظ على الجودة
- ترتيب الصور بالسحب والإفلات (Drag & Drop)
- تسمية كل صورة (اختياري): "أمامي" / "خلفي" / "تفصيل الطرف"
- حذف صورة مع تسجيل من حذفها ومتى (Audit)
- عرض الصور في معرض (Lightbox Gallery) داخل بطاقة الصنف
- **الحالات التي تستلزم رفع صورة إلزامياً:**
  - عند إضافة صنف جديد → صورة غلاف إلزامية
  - عند تغيير حالة الصنف إلى DAMAGED → صورة التلف إلزامية
  - عند إغلاق أمر الصيانة → صورة بعد الصيانة إلزامية

#### 📸 7.2 — صور الحجوزات (Booking & Rental Photos)

**كل حجز / عقد تأجير له 3 محطات صور إلزامية:**

```
محطة 1: قبل التسليم (Pre-Delivery Photos)
  ← تُلتقط لحظة التسليم قبل خروج الصنف
  ← صور حالة الصنف كاملة (أمام / خلف / تفاصيل)
  ← بطابع زمني (Timestamp) لا يمكن تعديله
  ← توقيع العميل على استلام الصنف بهذه الحالة

محطة 2: بعد الإرجاع (Post-Return Photos)
  ← تُلتقط فور استلام الصنف من العميل
  ← مقارنة بصور ما قبل التسليم (جانباً بجانب)
  ← تسجيل أي تلف أو فقدان مع تحديد موقعه على الصورة

محطة 3: صور التسوية (Settlement Evidence)
  ← عند وجود تلف: صور إضافية للتلف المكتشف
  ← صور تقرير الفحص (Inspection Report)
  ← إرفاق بالعقد وسند التسوية
```

**الشاشة المطلوبة — "توثيق التسليم":**
- زر "التقاط صورة" يفتح الكاميرا مباشرة
- عرض صور الصنف الأصلية (من بطاقة المنتج) بجانب الكاميرا
- إضافة ملاحظة على كل صورة (نص قصير)
- رسم دائرة أو سهم على الصورة لتحديد موضع التلف (Markup Tool)
- الحفظ يُوقّف التسليم حتى اكتمال الصور المطلوبة
- **قاعدة صارمة (BR-PHOTO-01):** لا يمكن إتمام التسليم بدون رفع صورة واحدة على الأقل

**الشاشة المطلوبة — "توثيق الإرجاع":**
- عرض صور التسليم القديمة والصور الجديدة جانباً بجانب (Side-by-Side)
- تحديد التلفيات بالضغط على موضع الصورة + اختيار نوع التلف:
  - `بقعة / تمزق / نقص في الزينة / كسر / فقدان جزء / تلف في التطريز / أخرى`
- إرسال صور المقارنة تلقائياً للعميل عبر واتساب عند اكتشاف تلف

#### 📸 7.3 — صور التأمينات (Collateral Photos)

**كل تأمين عيني يستلزم توثيقاً مصوراً إلزامياً:**

| نوع التأمين | الصور المطلوبة | ملاحظات |
|------------|---------------|---------|
| **ذهب** | صور من 3 زوايا + صورة وزن الميزان + صورة العيار | تُحفظ مشفرة |
| **سلاح** | صورة السلاح + صورة الترخيص (وجهان) | تُحفظ مشفرة بصلاحية خاصة |
| **وثيقة هوية** | صورة أمامية + صورة خلفية | تشفير AES إلزامي |
| **مجوهرات** | صور تفصيلية + صورة إيصال الشراء إن وُجد | — |
| **أصل عيني آخر** | صورتان على الأقل | — |

**سير عمل توثيق التأمين العيني:**
```
استلام الأمانة → التقاط الصور → إدخال البيانات → توقيع العميل على الاستلام
→ رقم إيصال فريد → حفظ مشفر → لا يمكن لأي موظف عرض الصور إلا بصلاحية خاصة
```

**عند إعادة التأمين:**
- عرض صور الاستلام الأصلية مقابل صور اللحظة الحالية
- توقيع العميل على استلام الأمانة سليمة
- أرشفة آمنة للصور لمدة 5 سنوات على الأقل

#### 📸 7.4 — صور الكوش ومشاريع التركيب (Kosha Project Photos)

**مراحل توثيق الكوشة بالصور:**

```
المرحلة 1: صور التصميم والموافقة
  ← صور مرجعية (Reference Images) من العميل أو كتالوج
  ← رسم أو صورة التصميم المتفق عليه
  ← توقيع العميل على التصميم

المرحلة 2: صور قبل الخروج من المستودع
  ← صور جميع مكونات الكوشة مرتبة
  ← قائمة فحص مصورة: كل مكون مصور مع اسمه
  ← توقيع موظف المخزن

المرحلة 3: صور أثناء التركيب
  ← صورة القاعة قبل التركيب (فارغة)
  ← صور مراحل التركيب (لا تقل عن 3 صور)
  ← صورة اكتمال التركيب النهائية

المرحلة 4: صور التسليم للعميل
  ← صور الكوشة مكتملة من زوايا متعددة
  ← صور مع العروس والعريس (اختياري - بإذن)
  ← توقيع العميل على الاستلام

المرحلة 5: صور الفك والإرجاع
  ← صور عند بدء الفك
  ← صور المكونات بعد الجمع
  ← توثيق أي تلف اكتُشف أثناء الفك
```

**معرض صور الكوشة:**
- ألبوم خاص بكل مشروع كوشة
- تصنيف الصور بالمرحلة تلقائياً
- قابل للمشاركة مع العميل عبر رابط خاص (مؤقت - 30 يوم)
- استخدام صور الكوشات المنجزة في كتالوج عرض للعملاء الجدد (بإذن)

### ✅ الوحدة 13: إدارة المهام (Tasks Module)

> **الفلسفة:** كل عملية في النظام يمكن أن تُولّد مهمة، وكل مهمة لها مسؤول واضح وموعد نهائي وحالة مرئية. المهام هي الجسر بين القرارات والتنفيذ الميداني.

---

#### 13.1 — أنواع المهام

**أ) المهام التلقائية (Auto-Generated Tasks):**
يولّدها النظام تلقائياً عند حدث معين:

| الحدث المُولِّد | المهمة المُنشأة تلقائياً | المكلَّف التلقائي | الأولوية |
|----------------|--------------------------|------------------|---------|
| تأكيد الحجز | "تجهيز الصنف وخياطته" | موظف الخياطة / المخزن | عالية |
| حجز مع بروفة | "موعد بروفة — العميل [الاسم]" | الخياط المسؤول | عالية |
| اقتراب موعد التسليم (48 ساعة) | "تسليم [رقم العقد] غداً" | موظف التأجير | عاجلة |
| إرجاع الصنف | "فحص الصنف [SKU] بعد الإرجاع" | موظف المخزن | عالية |
| اكتشاف تلف عند الفحص | "تقدير تكلفة تلف — [رقم العقد]" | المدير / الخياط | عاجلة |
| دخول صنف CLEANING | "غسيل وكي [SKU] — جاهز قبل [تاريخ]" | موظف الصيانة | متوسطة |
| دخول صنف REPAIR | "إصلاح [SKU] — الموعد النهائي [تاريخ]" | الخياط المسؤول | عالية |
| مخزون منخفض | "طلب شراء [اسم المستهلك]" | مدير المشتريات | متوسطة |
| قسط متأخر | "تحصيل قسط متأخر من [العميل]" | موظف المبيعات | عاجلة |
| جدولة تركيب كوشة | "التركيب في [القاعة] — [التاريخ والوقت]" | فريق التوصيل | عاجلة |
| جدولة فك كوشة | "فك الكوشة من [القاعة] — [التاريخ والوقت]" | فريق التوصيل | عالية |
| انتهاء صلاحية وثيقة تأمين | "تجديد وثيقة التأمين — [العميل]" | موظف المبيعات | متوسطة |

**ب) المهام اليدوية (Manual Tasks):**
يُنشئها أي موظف مخوَّل يدوياً لأي غرض:
- تكليف موظف بمهمة عامة
- متابعة عميل (Follow-up)
- مهمة تحضيرية أو إدارية
- مهمة خارجية (تواصل مع مورد، زيارة ميدانية، إلخ)

#### 13.3 — حالات المهمة ودورة حياتها

```
جديدة (NEW)
    ↓ (قبول المكلَّف أو بدء التنفيذ)
قيد التنفيذ (IN_PROGRESS)
    ↓ (إنجاز المكلَّف + رفع دليل)
بانتظار المراجعة (PENDING_REVIEW)  ← اختيارية لبعض الأنواع
    ↓ (اعتماد المدير)
مكتملة (COMPLETED) ✅
    
أو: مُلغاة (CANCELLED) — مع سبب الإلغاء
أو: مُؤجَّلة (POSTPONED) — مع موعد جديد
أو: مُعاد فتحها (REOPENED) — إذا لم تُنجز بشكل صحيح
```

#### 13.4 — شاشات وحدة المهام

**أ) شاشة "مهامي" (My Tasks):**
- قائمة مهام المستخدم الحالي مرتبة بالأولوية والموعد النهائي
- فلاتر سريعة: اليوم / هذا الأسبوع / متأخرة / كلها
- بطاقة كل مهمة تظهر: العنوان + الأولوية (لون) + الموعد + الكيان المرتبط
- ضغطة واحدة لتحديث الحالة إلى "قيد التنفيذ" أو "مكتملة"
- إشعار فوري لمنشئ المهمة عند الإنجاز

**ب) شاشة "لوحة المهام" — Kanban Board (للمديرين):**
```
[ جديدة ]    [ قيد التنفيذ ]    [ بانتظار مراجعة ]    [ مكتملة ]
  بطاقة        بطاقة               بطاقة               بطاقة
  بطاقة        بطاقة                                   بطاقة
```
- عرض مهام كل الفريق دفعة واحدة
- سحب وإفلات البطاقات بين الأعمدة لتغيير الحالة
- فلترة حسب: الموظف / النوع / الأولوية / الكيان المرتبط
- تلوين البطاقات المتأخرة باللون الأحمر تلقائياً

**ج) شاشة "قائمة المهام" — List View:**
- جدول كامل بكل المهام مع الفرز والفلترة والبحث
- تصدير إلى Excel / PDF
- إجراءات جماعية: تعيين لموظف / تغيير أولوية / إغلاق دفعة

**د) شاشة "إنشاء مهمة" — Quick Create:**
- نموذج مبسط: العنوان + المكلف + الموعد + الأولوية + الربط بكيان
- إنشاء سريع من أي شاشة (زر عائم "+" أو اختصار لوحة المفاتيح)
- قوالب مهام جاهزة للأنواع المتكررة

#### 13.5 — التعليقات والمرفقات داخل المهمة

- **خيط تعليقات (Comment Thread):** نقاشات بين المكلَّف والمكلِّف والمدير

- **تاريخ التعديلات:** كل تغيير في المهمة مُسجَّل مع التوقيت والمستخدم

## 🔷 الجزء الخامس: قواعد العمل الصارمة (Non-Negotiable Business Rules)
## ═══════════════════════════════════════

### قائمة القواعد الذهبية (لا يمكن تجاوزها):

| الرمز | القاعدة | التطبيق |
|-------|--------|--------|
| **BR-01** | منع الحجز المزدوج المطلق | DB Constraint + Service Layer + UI |
| **BR-02** | العربون شرط التأكيد | لا يتحول الحجز لـ CONFIRMED بدون عربون (≥25%) |
| **BR-03** | التأمين شرط التسليم | يُحظر تسليم أي صنف بدون تسجيل التأمين كاملاً |
| **BR-04** | الفحص شرط الإغلاق | لا يُغلق العقد بدون تقرير الفحص بعد الإرجاع |
| **BR-05** | التأمين التزام لا إيراد | التأمين لا يُحوَّل لإيراد إلا بعملية تسوية موثقة |
| **BR-06** | القيد المتوازن | SUM(Dr) = SUM(Cr) — رفض الترحيل عند أي اختلال |
| **BR-07** | المستند المُرحَّل لا يُحذف | تصحيح فقط عبر قيد/مستند عكسي |
| **BR-08** | الغسيل إجباري بعد الإرجاع | كل صنف مُرجَع → CLEANING لا يقل عن 24 ساعة |
| **BR-09** | لا حذف نهائي للبيانات المالية | Soft Delete فقط + Audit Log لكل تغيير |
| **BR-10** | الحساب المالي على الخادم | لا ثقة بالأرقام القادمة من العميل (Client) |
| **BR-11** | الصنف التالف لا يُؤجَّر | حالة DAMAGED تمنع الحجز حتى الإصلاح والفحص |
| **BR-12** | القطعة قابلة لعقد واحد فقط في نفس الوقت | فرض على مستوى DB + Service |
| **BR-13** | خصم الموظف بحد صلاحيته | خصم > 15% يحتاج اعتماد المدير |
| **BR-14** | سعر المستند يتجمد عند التوثيق | تغيير الأسعار لا يؤثر على المستندات المغلقة |
| **BR-15** | Audit Trail لكل عملية حساسة | من فعل + ماذا فعل + متى + قبل/بعد |
| **BR-16** | صورة غلاف إلزامية للصنف الجديد | لا يُحفظ الصنف بدون صورة واحدة على الأقل |
| **BR-17** | صور التسليم إلزامية | لا يكتمل التسليم بدون رفع صورة حالة الصنف |
| **BR-18** | صور التأمين العيني إلزامية | لا يُسجَّل أي تأمين عيني بدون صور موثقة |
| **BR-19** | صور التلف إلزامية عند الفحص | اكتشاف تلف → رفع صورة التلف إلزامي قبل المتابعة |
| **BR-20** | كل حجز مُؤكَّد يولّد مهمة تجهيز | تلقائياً عند انتقال الحجز لـ CONFIRMED |
| **BR-21** | مهمة التسليم تتطلب إنجازاً موثقاً | لا تُغلق مهمة التسليم بدون صورة دليل |
| **BR-22** | المهمة المتأخرة تُنبِّه المدير فوراً | بعد الموعد بـ 2 ساعة → إشعار تصعيد للمدير |
| **BR-23** | صور التأمين تُشفَّر وتُقيَّد بصلاحية | لا يرى صور التأمين إلا Owner والمدير |
| **BR-24** | صور الهوية تُشفَّر ولا تُعرض في واجهات عامة | عرض صور الهوية يتطلب تأكيد هوية الموظف |

## ═══════════════════════════════════════
## ⚠️ تعليمات نهائية مُلزِمة لمنصة البناء
## ═══════════════════════════════════════

```
1. لا تبنِ واجهات ديموية منفصلة عن البيانات
2. كل زر يجب أن يتصل بعملية حقيقية أو Mock واضح ومؤقت
3. كل وحدة تُبنى بـ: UI + Logic + Database + Validation + Permissions
4. لا Business Logic داخل مكونات الواجهة — كل المنطق في Services
5. الحسابات المالية تتم على الخادم فقط (Server-Side)
6. التحقق من الصحة (Validation) ثلاثي: UI + API + Database
7. كل عملية مالية ذرية (Atomic Transaction)
8. لا حذف نهائي للبيانات — Soft Delete فقط
9. كل تغيير حساس له سجل تدقيق (Before/After/User/Date/Reason)
10. منع التسليم بدون تأمين: فرض على مستوى الخدمة وقاعدة البيانات

-- قواعد الصور والوسائط
11. الصور تُخزَّن في S3/R2 — لا تُخزَّن في قاعدة البيانات مباشرة
12. الصور الحساسة (هوية/تأمين) تُشفَّر بـ AES-256 وتُعرض بـ Signed URLs
13. كل عملية رفع صور توثَّق: من رفعها + متى + لأي كيان
14. الصور ذات الطابع الزمني (تسليم/إرجاع) Timestamp غير قابل للتعديل
15. حذف صورة يتطلب صلاحية مدير + تسجيل في Audit Log
```

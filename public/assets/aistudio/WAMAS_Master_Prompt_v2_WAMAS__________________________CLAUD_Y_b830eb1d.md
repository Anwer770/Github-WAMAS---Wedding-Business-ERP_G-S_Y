### 1.1 — تعريف النظام

**WAMAS** — نظام تشغيل أعمال متكامل (Business Operating System) مخصص لإدارة محلات تأجير وبيع وتصنيع مستلزمات الأعراس. يجمع في منظومة واحدة:

- إدارة الحجوزات والتأجير والعقود
- التصنيع وأوامر الشغل
- المبيعات والمشتريات والموردين
- المخزون والأصناف والمستودعات
- المحاسبة المالية المزدوجة الكاملة
- إدارة العملاء (CRM)
- التأمينات والضمانات
- الصور والوسائط
- المهام والتكليفات
- الصلاحيات المرنة

### 1.2 — الدورة التجارية الكاملة
```
مورد ← شراء/تصنيع ← مخزون ← عرض سعر ← حجز ← عربون ← عقد ← تأمين
← تجهيز/تصنيع ← تسليم ← استخدام ← إرجاع ← فحص ← تسوية ← إغلاق ← محاسبة
```

### 1.3 — المعمارية التقنية الإلزامية

**Stack التقني:**
```
Frontend:  React 18 + TypeScript + Vite + Tailwind CSS
Mobile:    Capacitor (iOS + Android) — نفس كود الويب
Desktop:   Electron (Windows + macOS + Linux)
Backend:   Node.js + Express/Fastify + Prisma ORM
Database:  PostgreSQL (سحابي مركزي) + SQLite (محلي لكل جهاز)
Auth:      JWT + Refresh Tokens + bcrypt
Sync:      Outbox Pattern + Idempotency Keys + Conflict Resolution
Storage:   S3-Compatible (Cloudflare R2 / AWS S3) للصور والملفات
Cache:     Redis (للجلسات والقفل المؤقت)
```

**بنية قواعد البيانات:**
```

  - المصدر الرئيسي للحقيقة
  - تزامن مركزي
  - متاح عبر الإنترنت

SQLite (Local — كل جهاز):
  - نسخة محلية كاملة
  - يعمل Offline بالكامل
  - يتزامن مع PostgreSQL عند توفر الاتصال
```

### 1.4 — نظام المزامنة Offline/Online (Sync Engine)

**المبدأ:**
> كل جهاز (جوال / حاسوب / كاشير) يعمل بشكل مستقل تماماً. عند عودة الاتصال يتزامن تلقائياً مع الخادم المركزي.

**آلية العمل:**
```
1. كل عملية تُكتب محلياً أولاً في SQLite (Optimistic Write)
2. تُضاف للـ Outbox Queue مع Idempotency Key فريد
3. عند توفر الاتصال: Worker يرسل الـ Outbox للخادم
4. الخادم يتحقق من التعارضات (Conflict Detection)
5. قواعد حل التعارض:
   a. Server Wins: للعمليات المالية المُرحَّلة
   b. Last Write Wins: للبيانات العامة (بيانات عميل، ملاحظات)
   c. Merge: للقوائم المستقلة (تعليقات مهام)
   d. Flag for Review: عند تعارض الحجوزات
6. الخادم يُرسل Delta Sync للأجهزة الأخرى
7. كل جهاز يُطبق التغييرات محلياً
```

**مؤشر الاتصال:**
- شريط ملون في أعلى الشاشة: أخضر (متصل) / برتقالي (متزامن) / رمادي (Offline)
- عدد العمليات المعلقة في الـ Outbox
- آخر وقت تزامن ناجح

**قواعد Offline الإلزامية:**
- منع الحجز المزدوج: يُفحص محلياً أولاً ثم يُؤكَّد عبر الخادم عند الاتصال
- المبالغ المالية: تُحسب محلياً وتُعيد التحقق عند المزامنة
- الصور: تُحفظ محلياً وترفع للسحابة عند الاتصال

### 2.1 — مبدأ الصلاحيات

> النظام يعتمد Role-Based Access Control (RBAC) مرناً. المالك والمدير يستطيعان إنشاء أدوار مخصصة وتعديل صلاحيات كل دور من واجهة الإعدادات دون أي كود.

### 2.2 — الأدوار الافتراضية (قابلة للتعديل والحذف والإضافة)

| # | الدور | الوصف |
|---|-------|-------|
| 1 | **المالك (Owner)** | صلاحية كاملة — لا قيود — لا يمكن حذفه |
| 2 | **المدير العام** | إدارة كاملة بدون: حذف نهائي / إعدادات النظام الحساسة |
| 3 | **المحاسب** | كل العمليات المالية + شجرة الحسابات + التقارير المالية |
| 4 | **موظف مبيعات/استقبال** | العملاء + الحجوزات + الفواتير (بدون تقارير مالية) |
| 5 | **موظف تأجير** | دورة التأجير: تسليم + استلام + فحص |
| 6 | **الكاشير** | POS + قبض وصرف + الصندوق اليومي |
| 7 | **موظف مخزن** | الأصناف + التسليم/الاستلام بـ QR + الصيانة |
| 8 | **الخياط / التصنيع** | أوامر الشغل + أوامر التعديل + المقاسات |
| 9 | **موظف توصيل** | مهام التوصيل والتركيب الخاصة به فقط |
| 10 | **مدير مشتريات** | الموردين + أوامر الشراء + الفواتير الواردة |
| 11 | **مشاهد/تقارير** | قراءة فقط بدون أي تعديل |

### 2.3 — شاشة إدارة الصلاحيات (Permission Matrix Screen)

**من يملك الوصول:** المالك + المدير العام فقط

**ما تتيحه الشاشة:**
```
1. إنشاء دور جديد: اسم الدور + وصفه + اختيار الصلاحيات من قائمة
2. تعديل دور موجود: تغيير أي صلاحية بضغطة زر
3. نسخ دور: إنشاء دور بنفس صلاحيات دور موجود ثم تعديله
4. حذف دور: شرط ألا يكون لأي مستخدم نشط هذا الدور
5. مصفوفة الصلاحيات (Permission Matrix):
   - صفوف: الوحدات (حجوزات / مبيعات / مشتريات / محاسبة / ...)
   - أعمدة: الإجراءات (عرض / إنشاء / تعديل / حذف / اعتماد / طباعة / تصدير)
   - كل خلية: مفتاح On/Off
```

**مثال على مصفوفة الصلاحيات:**

| الوحدة | عرض | إنشاء | تعديل | حذف | اعتماد | تصدير |
|--------|-----|-------|-------|-----|--------|-------|
| الحجوزات | ✅ | ✅ | ✅ | ❌ | ❌ | ✅ |
| المبيعات | ✅ | ✅ | ✅ | ❌ | ❌ | ✅ |
| المشتريات | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| شجرة الحسابات | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| التقارير المالية | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| إدارة المستخدمين | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |

**شاشة إضافة مستخدم جديد (من قِبَل المالك أو المدير):**

| الحقل | النوع | الإلزامية |

**إجراءات إضافية:**
- تغيير كلمة المرور: يفعلها المستخدم بنفسه أو المدير/المالك

- إيقاف حساب: فوري — يُقطع اتصاله الحالي
- سجل تسجيل الدخول: IP + الجهاز + التوقيت لكل دخول

**قاعدة أمنية صارمة:**
> الصلاحية تُفرض على مستوى: UI + API + Database Row Level Security.

### 📅 الوحدة 3: محرك الحجوزات (Anti-Conflict Booking Engine)

**قاعدة التعارض الرياضية (DB Constraint إلزامي):**
```sql
التعارض = (existingStart < requestedEnd) AND (existingEnd > requestedStart)
```

**آليات منع التعارض:**
1. قفل الصنف مؤقتاً 10 دقائق عند بدء الحجز (Redis Lock)
2. فحص التداخل الزمني قبل الحفظ (Service Layer)
3. DB Constraint يمنع الحجز المزدوج حتى عند الكتابة المتزامنة
4. هامش 48 ساعة إجباري قبل وبعد كل حجز (Buffer للغسيل)
5. Optimistic Locking: version_number على كل سجل
6. عرض أقرب بديل متاح تلقائياً عند الرفض

**حالات الحجز (10 حالات):**
```
PENDING       بانتظار دفع العربون
DEPOSIT_PAID  دُفع العربون — في انتظار التأكيد
CONFIRMED     مؤكد — القطعة مقفلة
PREPARING     قيد التجهيز
READY         جاهز للتسليم
DELIVERED     مُسلَّم للعميل
RETURNED      مُعاد
COMPLETED     مكتمل ومُغلق
LATE          متأخر (تلقائي)
CANCELLED     ملغي
```

**التقويم التفاعلي:** يومي / أسبوعي / شهري / حسب الصنف — ترميز لوني لكل حالة

**سياسة الإلغاء (قابلة للإعداد في الإعدادات):**
- أكثر من 30 يوم: استرداد كامل
- 15–30 يوم: استرداد 50%
- أقل من 7 أيام: لا استرداد

```
إذا النتيجة سالبة → مديونية إضافية على العميل
```

#### 6.1 — أوامر التصنيع (Manufacturing Orders - MO)

**حقول أمر التصنيع:**

| الحقل | النوع | الوصف |
|-------|-------|-------|

#### 6.2 — قائمة المواد (Bill of Materials - BOM)

|-------|-------|

#### 6.3 — مراحل التصنيع (Production Stages)

يُمكن تخصيص مراحل التصنيع من الإعدادات. الافتراضية:

| # | المرحلة | المسؤول |
|---|---------|---------|
| 1 | قص الأقمشة | قاطع الأقمشة |
| 2 | الخياطة الأولية | الخياط |
| 3 | التطريز والزينة | مختص الزينة |
| 4 | الكي والتشطيب | موظف التشطيب |
| 5 | فحص الجودة | مدير التصنيع |
| 6 | التغليف | موظف المخزن |

كل مرحلة:
- مسؤول واضح + موعد إنجاز
- تعليقات + صور مراحل
- نسبة اكتمال (0-100%)
- تكلفة ساعات العمل

#### 6.4 — تكاليف التصنيع

```
تكلفة التصنيع الكاملة =
  تكلفة المواد الخام (من BOM)
+ تكاليف العمالة (ساعات × سعر الساعة)
+ تكاليف غير مباشرة (مخصصة أو نسبة)
= سعر التكلفة الإجمالي

عند الانتهاء:
  يُضاف الصنف للمخزون بسعر تكلفة التصنيع
  قيد محاسبي: المخزون (Dr) / حساب التصنيع (Cr)
```

### 🖼️ الوحدة 10: إدارة الصور والوسائط

#### 10.1 — صور المنتجات والفساتين

- حتى 10 صور + فيديو (60 ثانية) لكل صنف

- صور قبل / بعد الصيانة
- ترتيب بالسحب والإفلات
- Markup Tool: رسم دائرة / سهم / نص على الصورة

#### 10.2 — صور الحجوزات (3 محطات إلزامية)

```
محطة 1 — قبل التسليم:
  صور حالة الصنف كاملة + بطابع زمني غير قابل للتعديل
  توقيع العميل رقمياً على الاستلام

محطة 2 — بعد الإرجاع:
  مقارنة جانبية (Side-by-Side) مع صور التسليم
  تحديد التلف بالإشارة على الصورة + نوع التلف

محطة 3 — صور التسوية:
  صور إضافية للتلف المكتشف عند الاختلاف
```

#### 10.3 — صور التأمينات (مشفرة)

- كل تأمين عيني: صور إلزامية موثقة
- تشفير AES-256
- عرض مقيَّد: المالك + المدير فقط
- أرشفة 5 سنوات على الأقل

#### 10.4 — صور الكوشة (5 مراحل)

## 🔷 الجزء الخامس: الإعدادات الشاملة (Settings Module)
## ═══════════════════════════════════════════════════════

> **من يملك الوصول:** المالك (كل الإعدادات) + المدير (إعدادات محددة) + المحاسب (إعدادات مالية)

### 5.1 — إعدادات الشركة والفروع

```
اسم الشركة + الشعار
العنوان + المدينة + الدولة
رقم السجل التجاري
الرقم الضريبي
معلومات الاتصال (هاتف / بريد / موقع)
الفروع: إضافة / تعديل / إغلاق
المستودعات والأرفف
```

### 5.2 — إعدادات المستخدمين والأمان

```
إضافة مستخدم جديد (username + password)
تعديل بيانات مستخدم
إعادة تعيين كلمة المرور
إيقاف / تفعيل حساب
مصفوفة الصلاحيات (RBAC Matrix)
سياسة كلمات المرور (الطول / التعقيد / الانتهاء)
إعدادات الجلسة (مدة الانتهاء / عدد الجلسات المتزامنة)
سجل تسجيل الدخول
```

### 5.3 — الإعدادات المالية والمحاسبية

```
السنة المالية (البداية والنهاية)
العملة الرئيسية والفرعية
نسبة VAT (قابلة للتعديل)
شجرة الحسابات (إضافة / تعديل / إلغاء تنشيط)
الحسابات الافتراضية لكل نوع عملية
سياسة الإهلاك (النوع + النسبة + طريقة الحساب)
فتح / إغلاق الفترات المالية
حدود الاعتماد (من يعتمد أي مبلغ)
سياسة الخصم (الحد الأقصى لكل دور)
```

### 5.4 — إعدادات التأجير

```
نسبة العربون الدنيا (افتراضي: 25%)
نسبة التأمين الدنيا (افتراضي: 30%)
هامش الـ Buffer بين الحجوزات (افتراضي: 48 ساعة)
الحد الأدنى لمدة الغسيل بعد الإرجاع (افتراضي: 24 ساعة)
سياسة الإلغاء (النسب والمدد)
غرامة التأخير اليومية (افتراضي: 15% من سعر اليوم)
```

### 5.5 — إعدادات الإشعارات

```
تفعيل / تعطيل كل نوع إشعار
القنوات: داخلي / SMS / واتساب / بريد إلكتروني
المدة قبل التنبيه (مثلاً: 24 ساعة أو 48 ساعة قبل التسليم)
قوالب رسائل SMS والواتساب (قابلة للتعديل)
```

### 5.6 — إعدادات المظهر والنظام

```
اسم النظام واسم التطبيق
الشعار والألوان الرئيسية
اللغة الافتراضية (عربي / إنجليزي / ثنائي)
المنطقة الزمنية
تنسيق التاريخ والوقت
تنسيق الأرقام والعملة
Watermark الصور (تفعيل + شعار)
```

### 5.7 — إعدادات المزامنة والنسخ الاحتياطي

```
تكرار المزامنة التلقائية (1 دقيقة / 5 دقائق / عند الاتصال)
النسخ الاحتياطي التلقائي: يومي / أسبوعي
مكان النسخ: سحابة / محلي / كلاهما
استعادة من نسخة احتياطية
سجل المزامنة والتعارضات
```

### 5.8 — إعدادات الطباعة والمستندات

```
قالب الفاتورة (شعار / عنوان / معلومات ضريبية / تذييل)
قالب العقد
قالب سند القبض / الصرف
قالب كشف الحساب
حجم الورق الافتراضي (A4 / Thermal 80mm)
طباعة الباركود / QR على المستندات
```

### 5.9 — إعدادات التسعير والضرائب

```
سياسات التسعير الـ 8 (تفعيل / تعديل / إضافة)
نسب الضريبة (VAT) لكل فئة صنف
إعفاءات ضريبية
رقم التسجيل الضريبي على الفواتير
```

## ═══════════════════════════════════════════════════════
## ⚠️ تعليمات البناء الإلزامية لمنصات الذكاء الاصطناعي
## ═══════════════════════════════════════════════════════

```
البنية والكود:
1. لا واجهات ديموية منفصلة عن البيانات
2. كل زر متصل بعملية حقيقية أو Mock واضح ومؤقت
3. كل وحدة: UI + Logic + DB + Validation + Permissions + Sync
4. لا Business Logic داخل مكونات الواجهة
5. كل المنطق في Services/Domain Layer

المحاسبة:
6. الحسابات المالية على الخادم فقط (Server-Side)
7. Validation ثلاثي: UI + API + Database
8. كل عملية مالية ذرية (Atomic Transaction)
9. لا حذف نهائي — Soft Delete فقط
10. Audit Trail: من + ماذا + متى + قبل + بعد + السبب

الصور والأمان:
11. الصور في S3/R2 — لا في DB مباشرة
12. الصور الحساسة: AES-256 + Signed URLs
13. Timestamp الصور غير قابل للتعديل

المهام:
14. كل حجز مُؤكَّد → مهمة تجهيز تلقائياً
15. إلغاء الكيان → إلغاء مهامه التلقائية المعلقة

Offline/Sync:
16. SQLite محلي على كل جهاز
17. Outbox Pattern + Idempotency Keys
18. Conflict Resolution قابل للإعداد
19. مؤشر حالة الاتصال والمزامنة دائماً مرئي

المستخدمون:
20. كل مستخدم: username فريد + password مشفر (bcrypt)
21. الصلاحيات تُعدَّل من الواجهة بدون كود (Permission Matrix)
22. إيقاف حساب = قطع فوري لجميع جلساته النشطة
```
